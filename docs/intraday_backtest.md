# ETF 日内最佳买入时刻分析

本文介绍 ChickenFarm 的「日内择时」分析：回答**一个交易日内，固定在哪个时刻买入 ETF 平均成本最低**，以及这个结论在统计上是否显著、是否跨时间稳定。内容包括数据如何获取、如何长期累积，以及如何用这些数据做分析。

> 该功能从独立脚本 `etf_best_buy_time_sina.py` 演化而来，复用了周定投回测（见 [backtest.md](./backtest.md)）已验证的「多情景对齐 + 基准超额 + 显著性检验」方法论。本文结论仅为历史统计，**不构成投资建议**，历史规律不代表未来。

## 一、核心思想

一个朴素做法是：统计近几天每个盘中时刻（如 09:31、10:05……）的买入均价，取最小值宣布「最佳时刻」。这有两个致命问题：

1. **样本太少**：只看 1~5 天，一天里有约 240 个分钟时刻，纯靠噪声也必然产生一个最小值，属于多重比较下的「事后最优」；
2. **时刻间不对齐**：某时刻某天缺数据就跳过，会导致各时刻实际来自不同的日期集合，均值差混入「日期不同」的偏差。

ChickenFarm 的做法与周定投同构——**配对、对齐、减基准、做检验**：

```
   最近 W 个「完整交易日」（所有时刻共用同一组日期，严格配对）
  ┌────────────────────────────────────────────────┐
  │  日期 d1: 09:31 价, 09:32 价, … , 10:05 价, …  │
  │  日期 d2: 09:31 价, 09:32 价, … , 10:05 价, …  │
  │  …                                             │
  │  日期 dW: …                                    │
  └────────────────────────────────────────────────┘
        每个时刻 t 与「当日 VWAP 基准」比较，跨 W 天取中位数
```

- **基准 = 当日 VWAP**（成交量加权均价；成交量缺失时退化为当日分钟均价）。每个时刻的价格先除以当日 VWAP，抵消当天整体价格水位（市场 β），使不同日期、不同标的、不同窗口之间可比。
- **超额用 bps 表示**：`dev = (时刻价 / 当日VWAP − 1) × 10000`，负值表示该时刻比当日均价便宜。
- **跨日取中位数**：每个时刻在 W 天上有 W 个 dev，取中位数作为该时刻的相对成本。
- **显著且稳健才推荐**：最便宜的时刻还要通过配对显著性检验与分块稳定性判定，否则如实标注「无显著盘中择时效应」，不强行给结论。

## 二、数据获取

### 2.1 数据源与硬限制（重要）

分钟数据来自 akshare 的新浪分时接口 `stock_zh_a_minute`（封装在 [etf_intraday_mod.py](../src/module/etf_intraday_mod.py)）：

- 只取 **1 分钟**周期、**原始不复权**价（复权在分析层统一处理，与日线采集存原始价的口径一致）；
- 接口**写死返回最近 1970 根** 1 分钟 bar，且不接受起止日期参数。按每交易日约 240 根计算，**一次只能拿到最近约 8~9 个交易日**（实测 510050 返回 1970 行、覆盖 9 个交易日）；
- 因此**分钟历史无法一次性回填**，拿不到一周以前、更拿不到上市以来的分钟数据。

> 对比：周定投用的**日线**数据由 [etf_mod.py](../src/module/etf_mod.py) 采集，新浪主源一次返回最近 4000 根（约 16 年），那是另一条链路，与本文无关。

### 2.2 采集方式：串行 + 重试 + 每日累积

分钟接口配额很低、且容易限流（高并发时会返回非 JSON 或直接断连），所以采集链路被刻意设计成：

| 设计 | 原因 |
| :-- | :-- |
| **严格串行**，逐只请求，绝不多进程 | 接口配额低，并发会触发限流 |
| 每只 ETF 每次运行**只请求 1 次**（只要 1 分钟周期） | 不浪费配额去取 5/15 分钟 |
| 失败**指数退避重试 4 次**（1/2/4/8 秒） | 对抗偶发限流 |
| 单只最终失败记入 fails 并**继续下一只** | 一只失败不中断整轮 |
| 市场前缀沪 `51/56/58 → sh`、深 `15/16 → sz` | 新浪接口需要带交易所前缀 |
| 只采集清单中分类为 `etf` 的标的 | 场外基金无分时市价，不参与 |

采集到的分钟数据通过 [db_etf_intraday.py](../src/db/db_etf_intraday.py) **增量去重写入**本地 SQLite：每只 ETF 一张分表 `minute_<code>`，按 `datetime` 主键去重。当天重复运行不会产生重复行；**跨日重复运行则把新交易日追加进来，样本随天数累积**。

### 2.3 推荐使用节奏

由于每次只有最近 8~9 天数据，建议**每个交易日收盘后运行一次采集**，让数据库长期累积：

```bash
# 在仓库根目录，每个交易日收盘后执行（串行，耗时取决于标的数量）
python chick.py -intraday-fetch
```

- 累积满 **8 个完整交易日**后，最短窗口才开始出非占位结论；
- 默认还有 10/20/60 交易日窗口，需要相应累积更久才会有结果；在此之前对应子图灰底占位，属正常现象。

## 三、数据存储

| 表 | 粒度 | 列 | 写入方式 |
| :-- | :-- | :-- | :-- |
| `minute_<code>` | 1 分钟 bar | `datetime, open, high, low, close, volume` | 增量 upsert（按 datetime 去重），长期累积 |
| `etf_<code>` | 日线（既有） | `date, open, high, low, close, volume, adj_close` | 周定投链路整表 replace |

分钟表与既有 `tbl_<code>`（周定投结果）、`etf_<code>`（日线）完全独立，**新增分钟表不影响任何现有数据与回测结果**。

## 四、分析（回测）方法

分析实现在 [intraday_timing.py](../src/algorithm/intraday_timing.py)，绘图在 [intraday_plot.py](../src/plot/intraday_plot.py)。全程只读数据库、**不发起网络请求**。

### 4.1 识别「完整交易日」

按自然日对分钟数据分组，只保留当日分钟 bar 数达到阈值（默认 **≥ 230** 根）的交易日。这样：

- 上市首日（半天）、采集当天（盘中未收盘）等残缺日子被自动剔除，不再依赖「简单删掉第一天」；
- 盘中时刻网格直接从实际数据中提取，不硬编码 09:31~15:00。

### 4.2 前复权对齐

跨日比较价格必须复权。分析层用既有日线表的 `adj_close / close` 算出**日复权因子**，乘到当日各分钟的 OHLC 上，使分钟价口径与周定投日线回测一致：

- 某交易日缺因子 → 该日按因子 1.0 处理；
- 整个日线表缺失/异常 → 回退为原始价，并在图标题与 stats CSV 中标注 `unadjusted=True`，**不因复权不可用而中断分析**。

### 4.3 构造严格配对矩阵

取「最近 W 个完整交易日」，构造价格矩阵 `M[日期, 时刻]` 后做严格对齐：

1. 先删掉「在任一日期缺失」的时刻列；
2. 再删掉「在剩余时刻上仍有缺失」的日期行。

从而保证**所有时刻都使用完全相同的一组日期**计算，彻底避免旧脚本各时刻日期集合不一致的错配。

### 4.4 基准与超额

```
dev[d, t] = ( price[d, t] / vwap[d] − 1 ) × 10000     # bps，负=比当日均价便宜
excess[t] = median_d( dev[d, t] )                    # 跨日中位数
```

- 买入价默认用该分钟的 `open`（可用 `INTRADAY_PRICE_FIELD` 改为 `close` 或 `vwap`，后者取每根 bar 典型价 `(high+low+close)/3`）；
- VWAP = `Σ(price×volume)/Σvolume`，volume 全为 0 时退化为当日均价。

每个时刻另外输出：均值、标准差、**便宜天数占比**（dev<0 的天数比例）、bootstrap 中位数 95% 置信区间（对日期行重采样 1000 次，固定随机种子）。

### 4.5 显著性与稳定性

只对「中位数最便宜的候选时刻」做检验，避免对上百个时刻做海量两两比较：

1. **配对 Wilcoxon 符号秩检验**：该时刻的 dev 序列相对 0（=VWAP）做单样本双侧检验，输出 p 值与效应量 r；有效非零样本 < 6 时不做检验；
2. **分块稳定性**：把日期按时间先后切 4 块，看候选时刻是否在至少 60% 的块中都进入「块内最便宜前 K 名」（默认 K=5）；
3. **推荐判定**，四个条件同时满足才标记为推荐买入时刻：

```
完整交易日数 ≥ 8  且  p < 0.05  且  分块稳定  且  便宜幅度 > 单边交易成本
```

- 不满足时，图上区分「显著但不稳定（significant but unstable）」与「无显著盘中择时效应」；
- 单边交易成本取周定投同一套配置 `BACKTEST_SPREAD + BACKTEST_SLIPPAGE + BACKTEST_COMMISSION`（默认即万 5 ≈ 5 bps）换算为 bps。成本是各时刻的公共常量，**不改变时刻排序**，只用于判断「省下的价差是否够覆盖交易成本」。

### 4.6 分析窗口

默认对最近 **5 / 10 / 20 / 60 个完整交易日**四个窗口分别分析（`INTRADAY_WINDOWS` 可配）：

- 短窗口反映近期规律、噪声大；长窗口更稳定但反应慢；
- 某窗口对齐后完整交易日不足 **8** 个，标记为样本不足，对应子图灰底占位，不做检验、不进 stats CSV。

## 五、如何运行

CLI 入口在 [chick.py](../chick.py)，逻辑在 [farm.py](../src/farm.py)：

```bash
# 1) 采集（联网，串行，限频）：每个交易日收盘后跑，长期累积分钟数据
python chick.py -intraday-fetch

# 2) 分析出图（不联网）：只读库内分钟数据，按领域出图并导出 stats CSV
python chick.py -intraday

# 3) 一条龙：先采集，再分析出图
python chick.py -job intraday_job
```

- `-intraday-fetch` 与 `-intraday` 都受总开关 `INTRADAY_ENABLED`（默认 true）控制；
- 分析只处理「回测列表」中分类为 ETF 的标的，按其所属**领域**分别出图（与周定投小提琴图一致）。

### 配置项（仓库根 `.env`，全部可选）

复制 [.env.example](../.env.example) 得到 `.env`，取消注释即可覆盖默认值：

| 配置键 | 默认 | 说明 |
| :-- | :-- | :-- |
| `INTRADAY_ENABLED` | true | 日内择时总开关，false 时采集/分析入口直接跳过 |
| `INTRADAY_WINDOWS` | `[5, 10, 20, 60]` | 分析使用的最近完整交易日窗口（JSON 数组） |
| `INTRADAY_MIN_BARS_PER_DAY` | 230 | 判定完整交易日所需的当日分钟 bar 数下限 |
| `INTRADAY_PRICE_FIELD` | open | 买入价使用的分钟字段：`open` / `close` / `vwap` |
| `INTRADAY_TOP_K` | 5 | 稳定性判定中「块内最便宜前 K 名」的 K |
| `INTRADAY_FETCH_RETRIES` | 4 | 采集失败的退避重试次数 |

交易成本沿用周定投配置 `BACKTEST_SPREAD` / `BACKTEST_COMMISSION` / `BACKTEST_SLIPPAGE`；图与 stats 的导出开关复用 `BACKTEST_EXPORT_STATS`（默认 true），导出根目录复用 `EXPORT_AIP_PLOT_PATH`。

## 六、输出解读

### 6.1 图

按领域导出到 `EXPORT_AIP_PLOT_PATH/<日期>/intraday_<领域>.png`：

- **每一行**：一只 ETF；**每一列**：一个分析窗口（W5/W10/W20/W60）；同一行纵轴刻度统一，便于横向比较；
- 蓝色实线 = 各时刻相对 VWAP 的超额中位数（bps），蓝色半透明带 = bootstrap 95% 置信区间；
- **灰色虚线 y=0 = 当日 VWAP 基准**，线上方=比均价贵，线下方=比均价便宜；
- **红色点 + 注释**：显著且稳健的推荐买入时刻（标题含 `RECOMMENDED`）；
- 橙色字 `significant but unstable`：统计显著但跨时间块不稳定，不推荐；
- 灰色字 `no significant intraday timing effect`：无显著盘中择时效应（多数情况）；
- 灰底 `insufficient full-session days`：完整交易日不足 8 个，样本不够；
- 标题带 `(unadjusted)`：该标的日线复权因子不可用，本图按原始价计算。

### 6.2 stats CSV

导出到 `EXPORT_AIP_PLOT_PATH/<日期>/stats/<领域>_intraday.csv`（UTF-8-SIG，可用 Excel 直接打开），每行一个「ETF × 窗口 × 时刻」，列含义：

| 列 | 含义 |
| :-- | :-- |
| `code` / `name` | ETF 代码 / 名称 |
| `window` | 分析窗口（完整交易日数） |
| `price_field` / `unadjusted` | 使用的价格字段 / 是否未复权 |
| `n_days` | 该窗口实际参与配对的完整交易日数 |
| `time` | 盘中时刻 `HH:MM:SS` |
| `median` / `mean` / `std` | 相对 VWAP 偏离（bps）的中位数/均值/标准差 |
| `ci_low` / `ci_high` | 中位数 bootstrap 95% 置信区间（bps） |
| `cheap_ratio` | 该时刻比当日 VWAP 便宜的天数占比（0~1） |
| `best_time` / `best_median` | 该窗口最便宜时刻及其中位数（每行重复，窗口级常量） |
| `p_value` / `effect_size` | 候选最佳时刻相对 VWAP 的 Wilcoxon 检验 p 值与效应量 |
| `stable` / `recommended` | 是否分块稳定 / 是否最终推荐 |

## 七、局限与注意事项

- **分钟历史无法回填**：接口只给最近约 8~9 个交易日，长窗口（20/60）结论依赖每日坚持采集累积，这是数据源的硬限制；
- **样本天然重叠度高、天数少**：即使累积到 60 天，分钟级结论也应主要用于「验证是否存在稳定、可覆盖成本的盘中低成本时段」，而非寻找精确到某一分钟的神奇时刻；
- A 股 ETF 盘中价差、流动性随时段变化（开盘/尾盘价差更大），模型用固定成本近似，未建模时变价差与冲击成本；实盘能否按某分钟开盘价成交还受挂单与流动性约束；
- 复权依赖既有日线表的 `adj_close`（现金分红递推 + 可选拆分因子）；日线缺失时结果按原始价计算并明确标注；
- 与所有历史回测一样，**历史规律不代表未来**；多数标的在多数窗口可能本就「无显著盘中择时效应」，这本身就是有价值的结论。
