# 定投回测方式合理性分析

## 一、分析结论（Summary）

当前回测的**核心数学逻辑是正确的**，作为「周几定投收益分布」的探索性可视化工具基本可用；但作为**判断「周几定投更优」的决策依据，方法论上存在若干实质性缺陷**，其中最关键的是**各星期分组的买入起点 / 持有期限未对齐**、以及**按组取最大中位数带来的多重比较偏差**。直接据图中红色（best day）决定周几扣款，结论不可靠。

合理性分级：

- **成立**：份额/成本/收益率的计算、用累计净值处理分红再投资、固定结束日、多起始日扫描、按周期分层、小提琴图展示分布。
- **有偏 / 需谨慎**：星期分组的时间窗口未对齐、样本高度重叠导致有效样本量虚高、固定单一卖出日、用「max 中位数」选最佳日、未计入费用。
- **不适配**：标的多为场内 ETF，但回测用基金「累计净值」成交，与 ETF 实际按市价买卖不符。

3. [stupid.py](file:///Users/dodo/Desktop/ChickenFarm/src/algorithm/stupid.py#L44-L73) `invest_weekly`：在 `buy_df` 上，按每一行的 `weekday()` 归入 0–4（周一~周五），分别累计 `份额 total[w]` 与 `成本 count[w]`；最终都按同一个 `sell_price`（结束日 totvalue）卖出，得到 5 个收益率。`invest_daily` 则对区间内每天买入得到一个基准（图中金色 daily）。
4. [algorithm.py](file:///Users/dodo/Desktop/ChickenFarm/src/algorithm/algorithm.py#L54-L77)：`buy_df = value_df.iloc[start_index : end_index]`（**不含 end 当天**），`sell_price` 取 end 当天 totvalue。
5. [aip_plot.py](file:///Users/dodo/Desktop/ChickenFarm/src/plot/aip_plot.py#L45-L131)：每个「基金×周期」一个小提琴子图，6 把小提琴 = 周一~周五 + daily；`get_best` 取 6 者中**中位数最大**的下标标红。

收益公式（正确）：

```
份额 = Σ 1000 / 当日 totvalue
收益率 = (sell_price * 份额 - 投入成本) / 投入成本
```

## 三、合理性逐项评估

### 3.1 正确、值得肯定的点

1. **用累计净值 `totvalue` 成交**：自动包含分红再投资，避免用单位净值低估收益，方法正确。
2. **收益率定义为金额加权（实际定投 IRR 的简化）**：份额×卖出价减成本，符合定投真实盈亏，不是简单的价格涨跌幅。
3. **多起始日扫描**：不依赖单一时点，试图刻画「任意时间开始定投」的分布，思路正确。
4. **固定结束日 + 按周期分层**：在同一子图内各星期分组面对相同的卖出时点，横向比较基础一致。
5. **展示分布而非单点**：小提琴图 + 中位数 + 25/75 分位，比只看均值更能反映波动。

### 3.2 实质性缺陷（影响结论可信度）

**缺陷 1：各星期分组的「首次买入时点 / 持有期限」未对齐（最关键）**

- 一次 `start`（比如周三）下，周一组要等到 start 之后的第一个周一才首次买入，周三组在 start 当天就买入。
- 结果：不同星期组的**首次投入时间相差最多 5 个自然日，资金加权持有期限不同**。
- `buy_df.iloc[start_index:end_index]` 又统一以同一个 end 卖出，于是「越早买入的星期」系统性地持有更久。
- 影响：组间收益差里混入了「持有期限差」，无法归因于纯粹的「周几效应」。在趋势行情中这足以系统性地抬高某一工作日。

**缺陷 2：`get_best` 用「6 组中位数取最大」选最佳日 → 多重比较 / 过拟合**

- 在同一批历史数据上从 6 个选项里挑表现最好的，天然存在「赢家偏差」：即使全是噪声，也必有一个最高。
- 图中红色 best day 基本是「事后最优」，不具前瞻性。需要统计显著性检验 + 样本外验证才能称为「规律」。

**缺陷 3：起始日高度重叠，有效样本量被高估**

- 起始区间内相邻 start 仅相差 1 天，产生的买入序列绝大部分重合（自相关极强）。
- 60 个 start 并不等于 60 个独立样本，小提琴的样本量与分位数看起来很「稳」，实则独立信息有限，分布偏窄、易高估显著性。

**缺陷 4：固定单一卖出日，结论绑定卖出时点**

- 所有 start 都在同一个 end 卖出，收益分布很大程度反映「这一段到 end 的市场涨跌（β）」，而非周几效应。
- 换一个 end（不同市场环境），best day 可能改变。缺少对卖出时点的稳健性扫描。

**缺陷 5：短周期样本过少、噪声极大**

- 30 天周期 + 10 天起始区间：每次 start 的买入窗口约 30 个自然日，每个星期组仅约 4 次扣款，且各 start 高度重叠。
- 4 个点算一个收益率，再取中位数——短周期小提琴几乎被个别交易日主导，**30/60 天的周几结论参考价值很低**。730 天（每组约 100 次）才相对稳健。

**缺陷 6：未计入任何成本**

- 公式零费率：无申购费/赎回费、无买卖价差。
- 场外基金有申赎费（虽可能一折），持有 < 7 天还有 1.5% 惩罚性赎回费；周几切换不影响总费率，但「日定投 vs 周定投」「频繁调整」的成本比较被忽略。
- 数据里其实已采集 `buy_rate/sell_rate_info`，但回测未使用。

### 3.3 标的与成交方式不匹配

- 现列表几乎全是**场内 ETF**（5/1 开头代码），真实交易是按**二级市场市价**买卖，存在买卖价差、最小 100 份、成交时点价、折溢价。
- 回测却用基金 IOPV/累计净值成交，等于假设每天都能按净值无限额成交，**系统性低估了 ETF 的交易摩擦**，也无法反映盘中择时。
- 若意图是「场内 ETF 周几买入」，应使用 ETF 的**日线行情（开/收/均价 + 成交额）**而非累计净值。

### 3.4 工程层面的次要问题（不改变结论）

- `profit_rate DECIMAL(5,4)`：范围 −9.9999~9.9999，强行情下超范围会写库报错。
- 用**自然日** cycle（30/60…）而非交易日表达周期，实际定投次数随节假日漂移，跨周期口径不齐。
- `invest_daily` 用魔法数 `999` 表示错误，`week=-1` 表示 daily，属可读性问题。
- pandas 循环内反复 `pd.concat`（[backtest_mod.py](file:///Users/dodo/Desktop/ChickenFarm/src/module/backtest_mod.py#L50-L69)），数据量大时低效。

## 四、改进建议（按性价比排序，供选择是否实施）

| 优先级 | 建议 | 解决的缺陷 | 实施要点（仅说明，不在本分析阶段执行） |
| :-- | :-- | :-- | :-- |
| P0 | **对齐各星期组的持有窗口** | 缺陷 1 | 让每个星期组都从「start 之后该星期的第一个交易日」开始、并对每组使用「各自首次买入后相同长度」的结束日；或统一改为「固定 N 次扣款后卖出」，保证 5 组扣款次数与持有期限相同。 |
| P0 | **放弃「max 中位数」直接下结论，增加显著性检验** | 缺陷 2 | 对星期组做配对检验（如对同一 start 的 Mon vs Fri 配对差值的 Wilcoxon / t 检验），报告 p 值与效应量；仅当差异稳定且显著才标 best，否则标注「无显著差异」。 |
| P1 | **样本外 / 滚动验证** | 缺陷 2/3/4 | 前半段历史选 best day，后半段检验是否依然占优；或滚动 end 日（多个卖出时点）看 best day 稳定性。 |
| P1 | **降低重叠，用独立起点** | 缺陷 3 | 起始点按周/按 N 个交易日取样而非每个自然日；或用 block bootstrap 估计置信区间。 |
| P1 | **对 ETF 使用日线行情** | 标的不匹配 | 新增 ETF 行情数据源（开收盘价/成交额），买入按次日或当日收盘价并扣一个半价差，使回测贴近实盘。 |
| P2 | **计入费率与摩擦** | 缺陷 6 | 申赎费 / 买卖价差 / 滑点作为参数纳入收益计算，复用已采集的 `buy_rate`。 |
| P2 | **弱化短周期、统一口径** | 缺陷 5 / 工程 | 30/60 天明确标注「样本少、噪声大」或剔除；周期改用交易日表达；`profit_rate` 扩容（如 DECIMAL(7,4)）。 |

> 注意：行为金融中「周几效应」在 A 股长期看微弱且不稳定，且周定投各工作日差异在统计上常不显著。**对普通投资者，定投的主要收益来源是长期纪律与估值，而非挑选周几**；本回测更适合用来验证「周几差异确实很小、不必纠结」，而不是选出一个神奇的扣款日。

## 六、验证方式（若后续实施改进）

1. 对齐窗口后：同一 start 下 5 个星期组的**扣款次数、首末买入日期跨度应一致**（可断言）。
2. 报告每组配对差值的 p 值 / 置信区间，并在多个滚动 end 日上复算，检查 best day 是否稳定。
3. 用独立起点 / bootstrap 重画小提琴，对比改造前后分布宽度与中位数排序的变化。
4. 若接 ETF 行情，抽查若干笔买入价与真实日线、费用后金额是否可勾稽。
